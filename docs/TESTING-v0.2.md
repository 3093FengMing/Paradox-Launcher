# v0.2 测试指南

更新日期：2026-10-26。v0.2 增加下载队列、Java 管理、目录缓存与网络设置、实例导入 / 移除、每实例覆盖、运行期间关闭行为，以及自定义界面预设和简体中文 / English i18n。四组原版矩阵、61 项 Rust 测试、正式 release 构建与最终 exe 校验已通过，具体范围见 [验证记录](VERIFICATION.md)。

## 环境与隔离

最终 exe 路径为 `releases/v0.2.0/Paradox-Launcher-0.2.0-windows-x64.exe`；也可解压 `releases/Paradox-Launcher-0.2.0-windows-x64.zip` 后运行包内 exe。文件大小为 25,362,432 字节，SHA-256 为 `b5d2f6027a33e640e6de66cf1e57c4e8f5b6fc33bcd3cec0311c2591cc998158`，可用 `Get-FileHash` 与随包的 `SHA256SUMS.txt` 比较。Windows x64 需要 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，运行 exe 无需 Rust / Node / Vite。游戏安装需要网络，启动需要匹配的 Java；可在设置中检测、选择或下载运行时。

默认配置为 `%LOCALAPPDATA%/ParadoxLauncher/config.json`，默认游戏根目录为同目录下的 `minecraft/`。建议使用独立配置并在设置中将游戏目录改为测试目录；只指定 `PARADOX_CONFIG` 不会自动隔离游戏文件。

```powershell
$env:PARADOX_CONFIG = "$env:LOCALAPPDATA\ParadoxLauncher-v02-test\config.json"
& '.\releases\v0.2.0\Paradox-Launcher-0.2.0-windows-x64.exe'
```

首次运行应为空实例库。独立测试前关闭其他启动器进程；单实例机制可能将后续运行转为唤回已有窗口。

## 界面、缩放与持久化

1. 打开六个页面，切换沉浸式与现代工作台，确认两种界面使用相同实例与设置。
2. 自由缩小、放大、最大化、还原窗口。标题栏固定，正文独立滚动；细滚动条应融入主题，所有操作仍可滚动访问。
3. 修改主题、强调色、缩放、圆角、背景开关、模糊、遮罩、侧栏透明度与减少动效。即时预览应生效，“还原修改”恢复已保存值。
4. 保存设置，关闭并重开确认保留。创建两个实例，重命名其中一个，确认存储键和游戏目录不被名称修改。
5. 测试实例菜单和弹窗的方向键、Enter、Tab、Escape、初始焦点与焦点返回。

背景仍为 CSS 与占位图。高 DPI 和多显示器完整矩阵为后续发行验收项，原生窗口当次测试状态见验证记录。

## 自定义预设与语言

1. 在「设置与个性化 → 外观与体验」选择简体中文、English 或跟随系统。页面、弹窗与常用通知应即时切换；保存设置后重开应恢复语言。
2. 调整外观，点击「保存当前外观」并命名；尝试中文和 emoji。切换外观后应用该预设，确认全部外观参数恢复，再点击「保存设置」持久化当前外观。
3. 重命名预设，导出并复制 JSON。导出仅包含完整外观，不应含账户、游戏目录或 Java 路径。粘贴到导入弹窗，应生成另一个预设。
4. 输入损坏 JSON、缺失字段、越界数值或超过 32 KiB 的文本，确认显示错误、保留弹窗且已有预设不变。预设最多 32 个，名称为 1–48 个 Unicode 字符。
5. 将语言或游戏设置改为未保存的草稿，再重命名 / 导入 / 移除预设。重开后只恢复已保存的设置，证明预设库操作没有顺带提交草稿。
6. 取消移除确认，预设应保留；确认移除后当前外观应保持。尝试 320 × 240 与 120% 缩放，操作区应折行并能通过正文滚动访问。

上述新增交互已完成浏览器与存储测试；最终 exe 的完整原生交互仍可按本节复核。预设格式与翻译扩展见 [CUSTOMIZATION-I18N.md](CUSTOMIZATION-I18N.md)。

## Java 与实例设置

1. 在 Java 设置中点击检测，确认主版本、vendor、架构、来源与绝对路径可读。
2. 使用文件选择器选择已安装的 `java.exe`，检查当前路径；错误路径应显示原因。
3. 将全局 Java 留空，检查自动选择匹配游戏要求；显式错误主版本应拒绝启动并说明原因。
4. 按需要下载 Java 8 / 17 / 21 或填写其他主版本（例如 25）。下载进入队列，完成后校验并刷新检测结果；当前平台没有对应 JRE 时显示实际错误。
5. 打开实例设置，启用内存、Java、分辨率或附加参数覆盖，保存并重开。关闭覆盖后恢复继承全局设置。显式启用空 Java 代表自动选择，空参数清除该项全局参数。
6. 使用目录选择器导入完整游戏根目录，扫描并选择 Vanilla 实例。导入引用原文件，不复制资源；更换全局游戏目录不应改变导入实例的外部引用。
7. 在测试副本上移除实例记录，确认文件仍保留并可重新导入。文件删除需勾选并输入实例名称，保护共享资源与链接路径；该步骤会删除独立存档，只对可丢弃的测试实例操作。

1. 在空游戏目录选择版本并创建实例，检查离线用户名、Java 和内存，点击安装。
2. 添加多个安装 / Java 任务，确认任务排队，文件数、字节数、速率与当前阶段更新。任务运行时配置写入和启动操作应阻止冲突。
3. 取消运行中或等待中的任务，确认状态明确。重试取消 / 失败任务，已完成且通过校验的文件应复用，未完成内容继续下载。
4. 安装完成后启动游戏。就绪后自然退出，再次启动；检查日志与退出状态。再次安装 / 修复完整实例应传输 0 个资源文件。
5. 点击停止游戏，确认进程结束且状态完成。异常退出应显示失败原因，不保留虚假的运行状态。
6. 重启启动器后重新执行安装 / 修复，确认已完成文件复用。下载队列历史属于当前会话，重启后不自动恢复任务列表。

开发者可使用真实矩阵工具（会下载并启动游戏）：

```powershell
cargo run -p paradox-core --example verify_mvp -- 'F:\Paradox-v02-test\中文 空目录' '1.12.2,1.20.1,1.21.1'
```

使用全新绝对目录；每个游戏就绪后正常关闭窗口，工具会再启动一次。超时强制停止记录不满足自然退出验收。工具的 JSON 和日志为安装、运行与复用证据，视觉截图需另行检查。

## 网络、错误与关闭行为

1. 成功获取目录后刷新，检查来源与缓存时间；网络不可用时应回退已有缓存并显示警告，没有缓存时显示错误与重试入口。
2. 保存合理的超时、文件并发、重试次数、HTTP / HTTPS 代理和 Mojang 兼容镜像。无效协议或参数保存应被拒绝；镜像需提供匹配的元数据、assets 和 maven 端点。
3. 选择中文 / 空格绝对路径安装，检查目录切换的结果。无写入权限的测试目录应报错，不将失败安装标为完整实例。
4. 使用备份配置副本测试损坏 JSON：重启后显示配置错误且可关闭，原文件保持不变，配置写入被拒绝。恢复有效配置后重启。
5. 游戏 / 下载进行中关闭窗口，依次测试“返回启动器”、“隐藏窗口，继续运行任务”和“停止任务并退出”。隐藏后再次打开同一 exe 应唤回窗口；保持隐藏时任务结束应退出启动器。
6. 停止失败或任务无法及时结束时应保留窗口并显示原因。空闲时关闭应正常退出。
