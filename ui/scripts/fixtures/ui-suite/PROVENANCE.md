# Suite fixed fixtures

`TestWOFF.woff` and `TestWOFF2.woff2` are unchanged FontTools 4.60.1 test fonts from commit `af032c141b452f47f35e93f1c5ca2004f133cdcf`, under `Tests/ttx/data/`. Sources:

- https://raw.githubusercontent.com/fonttools/fonttools/af032c141b452f47f35e93f1c5ca2004f133cdcf/Tests/ttx/data/TestWOFF.woff — 1328 bytes, SHA-256 `d61259880ec1f7226de94ddd8e08a097ddf0b0b313049890708abce5e22fea0a`.
- https://raw.githubusercontent.com/fonttools/fonttools/af032c141b452f47f35e93f1c5ca2004f133cdcf/Tests/ttx/data/TestWOFF2.woff2 — 808 bytes, SHA-256 `d4d6a624b2a1ce317702dd2be6742b05244087984d5b30fd0a8917b1be616a8a`.

Font attribution: Copyright (c) 2015 by FontTools. No rights reserved. The complete upstream MIT license, Copyright (c) 2017 Just van Rossum, is retained in `LICENSE.fonttools` (SHA-256 `6787208f83f659ccbc2223b2fde952ffa6f7e8aca62f1a8a2bf5bc51bb1b2383`). The fonts are distinct CFF OpenType / TrueType fonts, both with six glyphs. Tests assert individual platform acceptance, not equal decoded font bytes.

`pixel.png`, `pixel.jpg`, and `pixel.webp` are original generated test artwork: a 3×2 canvas filled with RGB(17,85,153), encoded by Chromium 1234's `canvas.toDataURL` on 2026-11-01. No external artwork. Original bytes are preserved for all descriptor/digest and decoder checks. `browser-assets.json` holds the identical original files as canonical base64 for the explicit test-only browser fixture; it also copies the two existing builtin SVG source bytes for actual-policy acceptance.

`format-vectors.json` contains checked-in literal canonical/framed byte and SHA expectations for JS and future Rust. The fixture producer uses an independent scalar-order serializer plus Node SHA-256, never production canonical/digest code. It is not regenerated during tests. Prefix bytes, U32 big-endian lengths, UTF-8 byte counts, and array-sensitive manifest bytes are stored explicitly. Test mutations must differ from these literals.

`animated.png` adds one APNG default-frame `acTL`/`fcTL` pair with correct CRCs to the original generated PNG. `animated.webp` wraps the original generated VP8 frame chunk in one VP8X/ANIM/ANMF frame (3×2, 100 ms, replace mode); the original ICCP/VP8X chunks are not nested in ANMF. These generated format variants prove default-frame platform acceptance under D28, without asserting multi-frame playback. Neither fixture uses external artwork.

`archive-vectors.json` freezes byte-level stored/fixed/dynamic/degenerate and invalid DEFLATE vectors plus ordered ZIP metadata/descriptor vectors. These come from the small independent test bit writer and ordered raw ZIP writer, which intentionally permit malformed cases. They are not produced by the product scanners. The ZIP-output capacity test uses a frozen xorshift32 seed `0x6c8e9cf5`, 8 MiB PNG-prefixed byte sequences, and final asset length 8,356,534; the real pinned synchronous compressor produces exactly 33,554,432 bytes. A one-character ordinary central-entry comment produces exactly one additional byte and is rejected. This Node capacity check substitutes only platform decoding and makes no claim that it provides a font/raster engine; the browser fixtures provide real platform evidence separately.

## Additional Unicode, framing and archive boundary vectors

`generate-fix1.mjs` is an explicit fixture-authoring script, never imported or executed by product code or validation tests. It uses the independent ordered ZIP test writer, Node SHA-256 and its own scalar-order canonical serializer/U32 framer; no production canonical, digest or ZIP implementation supplies expected values. Running it preserves the original top-level vectors and adds the `fix1` section to `format-vectors.json`:

- `non_bmp` has a complete valid bundle with `Home.tsx`, U+E000 `.ts` and U+1F600 `.ts`. The literal framed stream orders U+E000 before U+1F600, while its manifest descriptor array retains its original order. Literal digest: `8c4895b85f31ca2e44c3728ef15302f2c7dce45bd0b14edcf5c8a5b76602ca57`.
- `boundary_pair` contains two complete source bundles. Path `a.ts` plus bytes `x.tsbc`, and path `a.tsx.ts` plus bytes `bc`, have the identical naive concatenation `a.tsx.tsbc`; their literal U32-framed file segments and complete framed digests differ. Digests: `628e0ba5d0dc69067b77d0345c9ac2b10925c17e9b1ac25dbf6975744031f15c`, `4164edb94409f5c3f70e420d8465d8b6b8081f915380fecba5b082267cac69b2`.
- `zip_variants` holds two literal base64 ZIP byte sequences for `non_bmp`, with different actual local/central entry order and DOS date/time fields. Both decode through the actual archive API to the same bundle and literal digest. The second ZIP places `suite.json` last.
- `split_utf8` describes the fixed 67,883-byte `split-invalid-utf8.paradox-ui`, SHA-256 `e24f8d6d64eac474a74b1e19f8331227ca151aac91be575e8de7eeddae6b6173`. A nonfinal stored DEFLATE block ends on a 65,536-byte compressed feed boundary; its 65,531-byte output ends in `c3`. The next final stored block emits `28 20 61`. The source descriptor and ZIP CRC describe those exact original bytes, but `c3 28` is invalid UTF-8. Tests observe the real pinned Inflate output callbacks `[65531,3]`, require fatal archive decoding and preserve the previous publication. The shared JSON includes literal archive/source hashes, byte count, source recipe and output chunk observations for future Rust consumers.

`oriented-6.jpg` is the original generated `pixel.jpg` with one 36-byte APP1/Exif record inserted after SOI. Its little-endian IFD0 has exactly one SHORT Orientation=6 entry; the SOF stays 3×2, and Chromium's displayed/default bitmap is 2×3. It is 797 bytes with SHA-256 `1dc861585c3a3139689184680e559f4bd95a120eb4be31bf9e7c289e68e28c3b`. No image pixels are transcoded or rewritten. It uses the same original generated artwork and is copied byte-for-byte into `browser-assets.json`.
